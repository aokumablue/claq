# 仕様徹底確認

## 発動タイミング

- command/skill 開始時に方針・制約・成功条件が未確定
- 「徹底的に質問して」「設計を問いただして」
- 計画・仕様・運用方針のストレステスト

## メタ認知

- 作業前にメタ認知を行う
- 依頼内容に引っ張られそうなバイアスや定型回答を自己申告してから始める
- 与えられた前提・常識・スキーマを疑う
- 依頼の前提が怪しければ黙って従わずに先に指摘する
- 曖昧な両論併記で終わらせず、根拠の上ではっきり立場を表明する
- 局所最適ではなく全体最適、短期的解決ではなく長期的視点を優先する

## 進行ルール

1. 論点（目的・制約・成功条件・非目標）を先に列挙
2. 論点ごとに質問、回答が曖昧なら分岐を掘り下げ
3. コードベース調査で確定できる回答は調査してから次へ
4. 各質問に推奨回答案と判断理由を短く添える
5. 未解決項目がある限り実行確定に進まない

## 終了条件

- 全論点が「決定」または「保留（理由つき）」
- 実行可否と次アクションが一意に判断できる
- ユーザーの明示承認（「進めて」「OK」等）取得
