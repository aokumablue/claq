# MCP 2026-07-28 — 前版からの破壊的変更

出典: <https://modelcontextprotocol.io/specification/2026-07-28/changelog> /
<https://blog.modelcontextprotocol.io/posts/2026-07-28/>

前版は `2025-11-25`。この改訂は**プロトコルをステートレス化**する破壊的変更であり、
学習データに残る MCP の形（`FastMCP`・`initialize`・セッション ID・GET SSE）は
ほぼ全て無効になっている。

## 削除されたもの（使ったら誤り）

| 消えたもの | 代わりに |
|---|---|
| `initialize` / `notifications/initialized` ハンドシェイク | 各リクエストの `_meta` が版と capability を運ぶ |
| `Mcp-Session-Id` ヘッダ / プロトコルレベルのセッション | サーバが発行したハンドルを**ツール引数**として渡す |
| HTTP GET エンドポイント（スタンドアロン SSE ストリーム） | `subscriptions/listen`（長命 POST レスポンスストリーム） |
| `resources/subscribe` / `resources/unsubscribe` | `subscriptions/listen` の opt-in |
| `ping` / `logging/setLevel` / `notifications/roots/list_changed` | ログ水準は `_meta` の `io.modelcontextprotocol/logLevel` で毎回指定 |
| `Last-Event-ID` による SSE 再開・再送 | 再開不可。切れたら新しい request ID で再送 |
| サーバ発の JSON-RPC リクエスト（sampling / elicitation / roots） | MRTR（`resultType: "input_required"` → クライアントが再送） |
| `notifications/elicitation/complete` / `elicitationId` | MRTR の再送。相関は `requestState` に自前で載せる |
| エラーコード `-32002`（resource not found） | `-32602`（Invalid Params） |

## 追加されたもの

- **`server/discover`**: サーバは実装必須。対応版・capability・身元を返す。
  Python SDK は自動応答するので自前実装は不要（実測確認済み）。
- **`resultType`**: 全 result に必須。`"complete"` か `"input_required"`。
  版が古く欠けている場合、クライアントは `"complete"` とみなす。
- **MRTR**: サーバが `InputRequiredResult`（`inputRequests`）を返し、
  クライアントが `inputResponses` を添えて**別の request ID**で再送する。
- **`ttlMs` / `cacheScope`**: `tools/list` `prompts/list` `resources/list`
  `resources/read` `resources/templates/list` の結果に必須。
  `cacheScope` は `"public"`（共有中間装置もキャッシュ可）か `"private"`。
- **ヘッダ**: Streamable HTTP の POST に `MCP-Protocol-Version` / `Mcp-Method` /
  `Mcp-Name` が必須。本文と不一致なら `-32020`（`HeaderMismatch`）で 400。
- **`x-mcp-header`**: ツール引数を `Mcp-Param-{Name}` ヘッダへ写す注釈。
  機微な値（パスワード・API キー・PII）には付けない。
- **エラーコード配分**: `-32000`〜`-32019` は実装定義（新規割り当て禁止）、
  `-32020`〜`-32099` は仕様予約。`-32020` HeaderMismatch /
  `-32021` MissingRequiredClientCapability / `-32022` UnsupportedProtocolVersion。
- **`extensions`**: capability に拡張を宣言できる。tasks はコア外の公式拡張
  （`io.modelcontextprotocol/tasks`）へ移動し、`tasks/get` ポーリング + `tasks/update`。

## 非推奨（新規実装では採用しない。最低 12 か月の猶予後に削除されうる）

- **Roots** — ディレクトリはツール引数・リソース URI・サーバ設定で渡す
- **Sampling** — LLM プロバイダ API を直接叩く
- **Logging**（`notifications/message`）— stdio は stderr、HTTP は OpenTelemetry
- **HTTP+SSE トランスポート**（2024-11-05）— Streamable HTTP へ
- **OAuth 動的クライアント登録（RFC 7591）** — Client ID Metadata Documents へ
- `includeContext` の `"thisServer"` / `"allServers"`

## `_meta` の予約キー

リクエスト側（`io.modelcontextprotocol/` 接頭辞は予約）:

| キー | 必須 | 内容 |
|---|---|---|
| `io.modelcontextprotocol/protocolVersion` | 必須 | 例 `"2026-07-28"` |
| `io.modelcontextprotocol/clientCapabilities` | 必須 | クライアント capability |
| `io.modelcontextprotocol/clientInfo` | 任意（SHOULD） | 名前と版 |
| `io.modelcontextprotocol/logLevel` | 任意 | このリクエストの最小ログ水準 |

必須欠落は `-32602`（HTTP は 400）。宣言されていない capability に依存したら
`-32021` を `data.requiredCapabilities` 付きで返す。

レスポンス側は `io.modelcontextprotocol/serverInfo` を毎回載せる（SHOULD）。
`clientInfo` / `serverInfo` は自己申告であり検証されない。**認可判断に使わない**。

## セキュリティ上の必須事項

- Streamable HTTP サーバは `Origin` を検証する（DNS リバインディング対策）。
  不正なら HTTP 403。ローカル実行では `127.0.0.1` にのみバインドする。
- `$ref` がネットワーク URI を指していても**自動で辿らない**。
  opt-in にする場合も既定は無効、ホスト許可リスト・タイムアウト・サイズ上限を課す。
- 合成キーワード（`anyOf` / `oneOf` / `allOf` / `if`）は深さ・部分スキーマ数・
  検証時間に上限を置く（DoS ベクタになる）。
- ツール入力は全て検証し、レート制限と監査ログを持つ。ツール注釈は信頼しない。
- ステートフルなハンドルは、認証済みサーバでは「名前であって権限ではない」。
  呼び出しごとに認可を再検証する。未認証なら bearer token 相当なので
  十分なエントロピー（UUIDv4 等）と有効期限を持たせる。

## 生成後に機械確認する禁止パターン（正本）

このパターンが唯一の正本である。SKILL.md は複製せずここを参照する
（2 か所に置くと片方だけ更新され、検査したつもりの穴が残る）。

生成したコードに対して実行し、**1 件でも当たったら旧仕様が混入している**:

```bash
grep -rnE 'FastMCP|Mcp-Session-Id|mcp_session_id|resources/(un)?subscribe|Last-Event-ID|logging/setLevel|elicitationId|-32002|notifications/(initialized|elicitation/complete)|ctx\.elicit\(|\.elicit_url\(' <生成先>
```

各パターンの意味:

| パターン | 何を捕まえるか |
|---|---|
| `FastMCP` | 2.x で `MCPServer` に改名。旧名でも動くため最も危険 |
| `Mcp-Session-Id` / `mcp_session_id` | 廃止されたプロトコルレベルのセッション |
| `resources/subscribe` / `resources/unsubscribe` | `subscriptions/listen` へ置換済み |
| `Last-Event-ID` | SSE 再開機構は削除済み |
| `logging/setLevel` | `_meta` の `logLevel` へ置換済み |
| `elicitationId` / `notifications/elicitation/complete` | 2025-11-25 のみの機構。削除済み |
| `-32002` | resource not found は `-32602` へ変更 |
| `notifications/initialized` | ハンドシェイク廃止 |
| `ctx.elicit(` / `.elicit_url(` | サーバ発リクエストの旧経路。ステートレス下では失敗する。MRTR（`Resolve` + `Elicit`）を使う |

`ping` と `initialize(` はパターンに**入れていない**。前者は英単語として、
後者は無関係な初期化関数として散文・コードに現れ、誤検出が多いため。
これらの混入はテンプレート由来では起きない（テンプレートがどちらも持たない）。

例外は 1 つだけ: 旧クライアントとの後方互換を**意図して**実装する場合。
その場合はコメントで対象プロトコル版を明記する。
