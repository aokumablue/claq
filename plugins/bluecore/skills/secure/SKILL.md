# セキュリティレビュー

## 発動タイミング

認証/認可実装・ユーザー入力/ファイルアップロード・新APIエンドポイント・シークレット/認証情報・支払い機能・機微データ保存/送信・サードパーティAPI連携・外部由来の文字列をプロンプト/エージェントへ渡す経路

## チェックリスト

該当箇所が無い節・テスト項目は見出しごと出力しない。N/A を列挙しない。

### 1. シークレット管理
- [ ] APIキー・トークン・パスワードがハードコードされていない
- [ ] 全シークレットが環境変数
- [ ] `.env.local` が .gitignore に含まれている

### 2. 入力検証
- [ ] 全ユーザー入力をスキーマで検証
- [ ] ファイルアップロード制限（サイズ・MIME・拡張子）
- [ ] ホワイトリスト検証（ブラックリストでない）
- [ ] エラーメッセージで機微情報を漏らしていない

### 3. SQLインジェクション
- [ ] 全DBクエリでパラメータ化クエリまたはプリペアドステートメント使用
- [ ] SQL に文字列連結を使っていない

### 4. 認証と認可
- [ ] トークンを httpOnly クッキーに保存（localStorage 禁止）
- [ ] 機微な操作の前に認可チェック
- [ ] RLS 有効化 / RBAC 実装

### 5. XSS
- [ ] ユーザー提供 HTML をサニタイズ
- [ ] CSP ヘッダー設定
- [ ] フレームワーク標準 XSS 保護を使用

### 6. CSRF
- [ ] 状態変更操作に CSRF トークン
- [ ] クッキーに `SameSite=Strict`

### 7. レート制限
- [ ] 全 API エンドポイントにレート制限
- [ ] 高負荷処理（検索・アップロード）には厳しい制限

### 8. 機微情報露出
- [ ] ログにパスワード・トークン・シークレットを出していない
- [ ] ユーザー向けエラーメッセージは汎用的

### 9. 依存関係
- [ ] 既知の脆弱性がない
- [ ] ロックファイルをコミット済み
- [ ] Dependabot 有効化

### 10. LLM / エージェントの信頼境界
モデルに渡す文字列はすべて実行される命令になりうる。以下は「入力検証」ではなく
**境界の設計**の問題であり、スキーマ検証では防げない。

- [ ] 信頼できない入力（取得したページ・ファイル内容・ツール出力・他エージェントの
      応答・過去セッションの記録）がプロンプトへ入る箇所を列挙できている
- [ ] 信頼境界マーカー（`<...>` 等の区切りタグ）を、入力側が偽装・早期終端できない
- [ ] 除去・無害化に失敗した入力は通さず捨てる（fail closed）。「消せなかったので
      そのまま残す」経路を作らない
- [ ] エージェントが自分の出力で自分の権限を広げられない（自己承認の禁止。
      昇格・承認は人間のゲートを通す）
- [ ] サブエージェントに渡す権限が課題に対して最小（不信な入力を読む主体に
      汎用の書き込み権限を与えない）
- [ ] 信頼できない入力を扱う正規表現が、入力量に対して線形。破局的バックトラッキング
      だけを見ない — 無界の属性部（`<tag[^>]*>`）や終端の無い開始タグの反復は、
      指数ではなく二次オーダーで落ちる。属性部を有界化し、入力長を変えて実測する

## テスト

- 未認証→401 / 無効トークン→401
- 権限なし→403 / 自分のリソースのみアクセス
- 無効入力→400 / 制限超過→429
- 区切りタグを本文に混ぜた入力→境界を越えない（早期終端・偽装の両方向）
- 無害化が失敗する入力→捨てる（例外時に原文が下流へ渡る経路が無い）
- エージェントの出力だけでは承認・権限の状態が変わらない
- 除去対象を大量に含む入力→入力長を変えて処理時間が線形に収まる
