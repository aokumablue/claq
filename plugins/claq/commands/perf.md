# 性能改善

## 停止点

止まるのは、ステップ1 で計測コマンドを決められないときだけ。
それ以外では、次の手順を予告して終わる要約・続けてよいかの伺い・作業を止めない判断事項の列挙・区切りや長さを理由にした報告で応答を終えず、ステップ5 まで進む。
報告や未決事項への推奨は、次のツール呼び出しと同じ応答に書く。

## 永続メモリ

- 参照: SessionStart が `<claq-memory>`（`status='active'` の知識）を注入済み
  - 追加で要るとき: `. "$HOME/.claq/env.sh"` のあと `claq_run claq.mem.cli search "..."`（クエリ例 `perf bottleneck {対象ファイルパス}`）
  - 本文が要る key だけ `claq_run claq.mem.cli show <key>`
- 記録: ステップ5 で、効いた・効かなかった最適化だけを `claq_mem_learn --kind pitfall` か `howto` で残す

## ステップ1: 計測コマンドを決める

次の順で決める。

1. `--cmd` の指定
2. リポジトリの既存ベンチ（`pytest-benchmark`・`npm run bench`・`go test -bench` 等）
3. 対象の遅い処理を呼ぶ最小のスクリプトをスクラッチに書く（コミットしない）

決められなければ、何を測ればよいかを利用者に聞いて止まる。

## ステップ2: before を測る

1. 計測コマンドを 3 回実行し、中央値を before にする
2. プロファイラ（`cProfile`・`node --cpu-prof`・`pprof` 等）で時間の上位 5 件を取る
3. 3 回のばらつき（最大と最小の差）をノイズ幅として記録する

## ステップ3: 改善

`claq:code-refiner` を起動する。依頼文に次を書く。

- `mode: perf`
- 対象パス
- 計測コマンド・before の中央値・プロファイル上位 5 件
- 目標値（`--target` があれば）

## ステップ4: after を測って判定する

1. テストを実行する。red になったら、そのファイルの変更を逆適用で戻す
2. 計測コマンドを 3 回実行し、中央値を after にする
3. 改善がノイズ幅以下なら、ファイルごとに戻して測り直し、効いた変更だけ残す
4. `claq:reviewer` で差分をレビューする。BLOCKER のあるファイルは変更を戻す

## ステップ5: 報告

```text
Perf
──────────────────────────────
Command:  {計測コマンド}
Before:   {中央値}（ノイズ幅 {幅}）
After:    {中央値}（{改善率}%）
Kept:     {残した変更}
Reverted: {戻した変更と理由}
──────────────────────────────
```

## 引数

- 位置 #1: `[対象パス]`（省略時: プロファイル上位の関数があるファイル）
- `--cmd "<計測コマンド>"`: 計測に使うコマンド
- `--target <目標値>`: 目標値。届いたら追加の改善はしない
