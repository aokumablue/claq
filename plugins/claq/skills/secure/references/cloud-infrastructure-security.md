# クラウド・インフラの穴の観点

`../SKILL.md` の手順3 と同じ条件で当てる。
攻撃者が得るものを 1 行で書けた項目だけを穴にする。

## IAM

- ストレージ（S3 等）が公開 ACL になっていない。得るもの: 保存データの読み出し
- 実行ロール・CI のロールが `*`（全アクション×全リソース）を持たない。得るもの: 鍵 1 つの漏洩でアカウント全体
- 本番でルートアカウントの鍵を使っていない。得るもの: 同上

```yaml
# PASS: 必要なリソースへ必要な read だけ
permissions: [s3:GetObject, s3:ListBucket]
resources: [arn:aws:s3:::my-bucket/*]
```

## シークレット

- シークレットがコード・IaC・CI 設定・コンテナイメージに無い。得るもの: リポジトリやイメージを読めた人への鍵の流出

## ネットワーク

- DB と管理ポート（SSH/RDP）が `0.0.0.0/0` へ開いていない。得るもの: 外部からの直接接続
- 機微データの通信が TLS である。得るもの: 経路上での盗聴

## CI/CD

- 外部の PR で動くジョブ（`pull_request_target` 等）がシークレットと書き込み権限を持たない。得るもの: フォークからのシークレット窃取
- シークレットを持つジョブのサードパーティ Action をコミット SHA で固定している。得るもの: Action の乗っ取りでシークレット取得

## エージェント実行基盤

不信な入力を読むエージェントは、注入 1 回でその権限範囲を攻撃者に渡す。

- 本番の書き込み権限と長命な鍵を渡していない。得るもの: ロールの権限範囲すべて
- 認証情報を、エージェントが読める環境変数・ファイルに置いていない。得るもの: プロンプト経由での鍵の出力
- シェルを持つエージェントが、クラウドメタデータ（`169.254.169.254`）とホストの認証情報ディレクトリへ届かない。得るもの: 実行基盤の鍵
- 接続するツールサーバ（MCP 等）が、認証なしで公開ネットワークに出ていない。得るもの: ツールの直接実行
- 不可逆な操作（デプロイ・削除・権限変更・外部送信）の承認を、エージェント自身の出力で満たせない。得るもの: 人間を通らない不可逆操作
