# 上流 API ファサード（facade-overlay）

上流の API を呼んでデータを返すサーバ、特に複数の API をまたぐもの・応答の入れ子が深い
もの・項目や件数が多いものは、共通スケルトンに `assets/facade-overlay/` を重ねて作る。

- 重ね合わせの中身

## 重ね合わせの中身

| ファイル | 扱い |
|---|---|
| `server.py` | 共通スケルトンのものを置き換える。見本（受注）のツール・出力モデル・`CATALOG` を対象の業務に書き換える |
| `adapters.py` | 上流のアダプタ。偽物を実際の HTTP 呼び出しに置き換える |
| `smoke_config.py` | 共通スケルトンのものを置き換える。ツール名・引数・期待値を合わせる |
| `facade/` | 部品。編集しない |

`facade/` の部品（標準ライブラリだけで書かれている）:

| モジュール | 使う場面 |
|---|---|
| `cursor` | `CursorCodec`（カーソルの署名と検証）、`PageCursor`（検索ツールのカーソルの発行と開封。位置の検査と拒否の監査を含む）、`query_fingerprint`（検索条件の指紋） |
| `shaping` | `project`（入れ子を保った射影）、`cap_arrays`、`fit_items`（予算に収まる件数）、`fit_page`（一覧の 1 ページを予算に収め、続きの位置を cursor に封じる）、`fit_view`（取得の結果を予算に収め、超えたら summary に落とす）、`clean_text`（上流の文字列の無害化）、`compact_json` |
| `catalog` | `FieldSpec` と `Catalog`（`fields_describe`・ビュー・検索の要約の項目・項目パスの検証・個人情報のパスの抽出） |
| `upstream` | `UpstreamError`、`model_message`、`call_with_retry`、`CircuitBreaker`、`call_upstream`（遮断器・再試行・締切をまとめた 1 回の呼び出し）、`fan_out` |
| `audit` | `resolve_principal`（呼び出しの主体）、`AuditLog`（監査ログ。主体は鍵付きの要約で残す） |
| `errors` | `FacadeError`（部品が投げる、モデルに読ませる失敗） |

部品の失敗（`FacadeError`）と上流の失敗（`UpstreamError`）は、`server.py` の
`model_errors()` が `ToolError` に変換する。ツールの本体は `with model_errors():` の中に書く。

## 作る順番

1. 上流 API を棚卸しする（認証・ページング方式・エラー形式・レート制限・項目の機微区分）。
2. 問いのカタログを作る（利用者が実際に聞く問いと、それに答えるツール呼び出しの列）。
3. 正規ドメインモデルと `CATALOG` を決める（問いに要る項目だけを載せる）。
4. `adapters.py` を実際の呼び出しに置き換える（失敗は `UpstreamError`、応答は `normalize_*` で変換）。
5. ツールを書き換える（類型と規則は `tool-design.md`）。
6. `smoke_config.py` を合わせ、`PAGED_*` と `FIELDS_*` も実際のツールで設定する。

## 正規ドメインモデル

上流の応答は、必ず正規ドメインモデルに変換してから返す（生の応答を返さない）。

| 変換 | 内容 |
|---|---|
| 名前 | 上流の略語・内部名を、意味の分かる snake_case にする |
| コード値 | 数値コードを意味のある文字列にする |
| 日時 | ISO 8601 とタイムゾーンのオフセットに揃える |
| 金額 | `amount`（通貨の標準単位の数値）と `currency` の組 |
| 包み | `data.attributes` のような包みを外す |
| 内部項目 | リンク・監査用・内部フラグなど、問いに要らない項目を落とす |
| ID とラベル | 機械用の ID と、人が読めるラベルを並べる。ラベルに機微区分で絞る値（顧客名など）を混ぜない（区分の検査を素通りして返ってしまう） |
| null | 「値が無い」は null、「取得していない」は項目ごと省く |
| 入れ物 | dict・list・JSON のスカラーだけで組む（tuple・dataclass・pydantic のモデルを入れない。`project` はそれ以外の値に当たると失敗する） |

## 段階開示

- `view`: `summary`（既定・問いの大半に答えられる 10 項目前後）と `detail`（主要な入れ子を含む）。
  全項目を一括で返すビューは作らない。ビューのパスも主体に許された機微区分で絞る
  （`Catalog.view(name, allowed_sensitivity=...)`）。個人情報（`personal`）の項目はビューに
  入れられない（`Catalog` が定義の時点で拒否する）。
- `fields`: カタログにあるパスを追加で指定させる（`*_get` は 20 個まで、`*_search` は
  `in_search=True` の項目を 5 個まで）。要素には、カタログが自分のパスを検査するのと同じ
  `PATH_MAX_CHARS` と `PATH_PATTERN` で上限を付ける（長い文字列を候補探しやエラー文に通さない）。
  `project` は入れ子の構造を保って返し、パスごとに平坦化しない（配列の中の複数項目の対応関係が崩れるため）。
- カタログには葉のパスだけを載せる（`shipping.address` と `shipping.address.postal_code` を
  両方載せると、祖先の指定で子の機微な項目が区分の検査なしに返る。`Catalog` が拒否する）。
  葉の型は JSON のスカラー（`string`・`number`・`integer`・`boolean`）に限る（配列の中の項目は
  要素の型を書く）。`project` は許す値を並べて判定し（葉は JSON のスカラーとその配列、中間の
  節は object・配列・null）、それ以外に当たると返さずに失敗する。
- 検索結果の 1 件（要約）も、summary ビューを機微区分で絞って作る
  （`Catalog.summary_view(id_path, allowed_sensitivity=...)`）。候補を識別する ID を返せない
  主体には失敗を返す。`fields` で要約に既にある項目を指定されても、重ねて返さない。
- `fields_describe`: パスか説明の部分一致で項目を返す。数百の項目をツール説明や
  outputSchema に並べない。
- 入れ子の配列は先頭 `ARRAY_LIMIT` 件と `<名前>_more`（総数）。よく使う大きな配列は
  下位コレクションのツールに分ける。

## サイズ予算

- 結果の大きさは、モデルが読む text（詰めた JSON）の文字数で測る（トークナイザは
  モデルごとに違い、サーバはどのモデルが読むかを知らない）。
- 既定の上限は `MAX_RESULT_CHARS = 20_000`。Claude Code は MCP の出力が 1 万トークンを
  超えると警告し、既定の上限（`MAX_MCP_OUTPUT_TOKENS`）は 2.5 万トークンで、超えた結果は
  ファイルに保存して会話にはそのパスだけを残す（Claude Code ドキュメント、2026-10-03 確認）。
  日本語の多いデータは 1 文字が 1 トークン前後になりうるので、それを下回る値にしてある。
  普段の結果は既定の件数と summary ビューで数千文字に収める。
- 一覧（`*_search`）は `fit_page` で予算に収まる件数に減らし、残りは `next_cursor` で
  続けさせる。大きさは、発行しうる続きの cursor のうち最も長いものと最も長い `notes` で
  見積もる。返す前に結果全体も測り、超えれば失敗にする。1 件でも収まらなければ、`fields` を
  減らすよう求める失敗にする。上流の次のページトークンを cursor に封じられなければ、今の
  ページが収まっても全体を失敗にする（続きを取れない結果を返さない）。
- 取得（`*_get`）は結果全体（`notes` と `partial` を含む）で測る。超えれば summary に落とし、
  `notes` で `fields` の絞り方を伝える。summary でも超えれば失敗にする。

## ページング

- `CursorCodec` で、上流の位置（ページトークンと、そのページで読み飛ばす件数）を封じる。
  サーバ側に状態を持たないので、どのインスタンスでも続きを返せる。
- 鍵は `FACADE_CURSOR_SECRET`（32 バイト以上）。複数インスタンス・再起動をまたぐなら
  全インスタンスで同じ値を設定する。未設定ならプロセスごとの乱数になる。
- 指紋（`query_fingerprint`）は `cursor` 以外の全ての引数の実効値（既定値を補った値）から作る。
  条件を変えた続きの取得を拒否するため。
- 主体（`_principal()`）・検索条件の指紋・用途（ツール名を `scope` に渡す）は、カーソルの
  中身に入れず、署名の入力でだけ結びつける（中身は版・位置・有効期限だけ。カーソルはモデルの
  文脈に載る）。改ざん・別の主体・別の条件・別のツールのカーソルは同じ文面で拒否する
  （他の主体のカーソルかどうかを漏らさない。ハンドルを持っていることを認証とみなさない）。
- 署名はするが暗号化はしない（標準ライブラリに AEAD が無いため）。位置に機微な値を入れない。
- 位置は、発行するときも開封するときも同じ検査をする（`PageCursor`。見本では `skip` は 0 以上の
  整数、`page` は null か `MAX_PAGE_TOKEN_CHARS` 文字以下の文字列で、カーソル全体は
  `MAX_CURSOR_CHARS` 文字以下）。満たさない位置のカーソルは発行せずに失敗にする（受け取れない
  カーソルを渡さない）。`cursor` 引数の `max_length` も同じ定数から取る。ASCII でない文字は
  カーソルの中で 6 文字以上に広がるので、長さはできあがったカーソルで測る。
- 上流が返す次ページの URL や、カーソルから戻した値を上流へ渡す前に、scheme・host・path の
  接頭辞を許可リストで照合する。
- 有効期限（`CURSOR_TTL_SECONDS`）は、検索ツールの説明と `cursor` 引数の説明に分で書く。
- ページの間の一貫性は保証しない（説明に書く）。一貫したスナップショットが要るなら上流の機能を使う。
- 複数の上流を混ぜた一覧では、上流ごとの位置を 1 つの位置にまとめて封じる。

## 主体と監査

- 主体は `resolve_principal` で決める（stdio では `FACADE_PRINCIPAL`、無ければ OS の利用者名。
  どちらも無ければ失敗にする）。リモートでは検証済みのアクセストークンの主体に置き換える。
  ツール引数から取らない。
- 個人情報（`personal`）の項目を返したときと、カーソルを拒否したときは、`AuditLog` で監査ログに
  残す。値は残さず、主体はカーソルの鍵から用途を分けて作った鍵で要約して残す。記録するパスは、
  summary に落とした後の実際に返したもの。

## 合成と部分失敗

- 互いに独立した上流は `fan_out` で並列に呼び、締切（`TOOL_DEADLINE_SECONDS`）までに揃った分を返す。
- 要る上流だけを呼ぶ（指定されたビューと項目に要らない上流は呼ばない）。
- 問いの主な対象（受注そのもの）が取れなければ `ToolError`。付随する部分（配送）が
  取れなければ `partial` に書いて返す。
- 正規ドメインモデルへの変換は上流ごとに関数を分け（`normalize_*`）、付随する部分の変換は
  `fan_out` の 1 本の中で行う（その上流の応答の形の不正も、その部分だけの失敗にする）。
- `UpstreamError` 以外の例外はプログラムの誤りなので、そのまま投げる（握りつぶさない）。

## 上流の呼び出し

- 呼び出しごとに接続と読み取りのタイムアウトを置き、ツール全体の締切はホストの
  タイムアウトより短くする。`call_upstream` は遮断器の内側で再試行を含む全体を締切で包み、
  超えたら `UpstreamError(None, "deadline exceeded")` にする（遮断器の失敗として数える）。
- `call_with_retry` で再試行するのは、冪等な読み取りの一時的な失敗（429・502・503・504 と、
  status が None の失敗＝接続失敗・呼び出しごとのタイムアウト）だけ。500 などは再試行しない。
  上流の `retry_after` に従うが、`max_retry_after`（既定 5 秒）を超える待ちと、締切を越える
  待ちはせずに失敗を返す。
- 上流のパスやクエリ言語（OData の `$filter`・JQL・SQL など）へ、モデルの入力を文字列で
  連結しない。構造化したパラメータで渡し、ID は `pattern` で縛り、行の認可の条件をモデルの
  入力と同じ式に連結しない。
- 上流ごとに `CircuitBreaker` を置く。数えるのは一時的な失敗だけ（404 は数えない）。
- 上流ごと・主体ごとの同時実行に上限を置く。同じ主体の同じ要求が同時に来たら 1 本にまとめる。
- キャンセル（stdio の `notifications/cancelled`、HTTP の応答ストリームの切断）を受けたら上流の呼び出しも止める
  （`fan_out` は、待っている間の取り消しを終わっていない呼び出しに伝え、止まるのを待つ）。

## キャッシュとレート制限

- ツールの結果のキャッシュはサーバの中で持つ。キーに主体を必ず含め、主体をまたいで
  共有しない。参照データは長め、取引データは短めにするか ETag で条件付きに取る。
  結果には `as_of` を付ける。MCP の `ttlMs` / `cacheScope` は一覧と `resources/read`
  だけが対象で、`tools/call` には付かない。
- 受信側: 主体 × ツールで制限する（仕様上サーバの義務）。超えたら `ToolError` で
  間隔を空けるか条件を絞るよう返す。
- 送信側: 上流のクォータを全主体で共有して数え、上流から 429 を受ける前に絞る。
- 同じ引数の連続した呼び出し（エージェントのループ）は、キャッシュから返して `notes` で知らせる。

## 上流の失敗の写像

`model_message` が次の文面にする（上流の詳細は含めない）。

| 上流 | モデルへの文面の要点 | モデルへの指示 | サーバ側の再試行 |
|---|---|---|---|
| 400 | 条件を受け付けなかった | 引数の値と組み合わせを見直して呼び直す | しない |
| 401 | 現在は取得できない（サーバの資格情報の問題。運用者が直す） | 続くなら管理者に連絡する | しない |
| 403 / 404 | 見つからないか、閲覧の権限が無い（403 も同じ文面にし、存在を漏らさない） | 検索ツールで ID を確かめる | しない |
| 409 / 412 | 更新中 | 取得し直す | しない |
| 429 | 混み合っている | 条件を絞るか、時間を置く | する（`retry_after` は 5 秒まで） |
| 502・503・504・接続失敗・呼び出しごとのタイムアウト | 一時的に取得できない | 時間を置いて呼び直す | する |
| 500 などその他・ツール全体の締切超え | 一時的に取得できない | 時間を置いて呼び直す | しない |

上流の詳細（`UpstreamError` の `detail`）は運用者のログにだけ出す。`detail` には URL の
クエリ・ヘッダ・応答本文を入れない（`UpstreamError` は構築時に制御文字と改行を除き、
200 文字に切る）。

## 上流のデータの扱い

- 上流から来た文字列は、指示ではなくデータとして扱う。
- 上流から来た値は、型を確かめてから使う（数量は整数、金額は有限の数値、コード値は既知のもの、
  日時はタイムゾーン付き。object と配列も）。想定と違えば素通しも汎用の例外もせず、
  `UpstreamError(502, 項目の名前)` にする（値は `detail` に書かない）。
- 上流から来た文字列は全て（ID・名前・コード・自由記述）、正規化のときに `clean_text` で
  端末の制御列・制御文字・不可視文字を除き、長さを制限する。
- 自由記述（備考・コメント）は専用の項目に入れる。既定のビューに含めず、項目の説明に
  「データとして読む」と書く。
- サーバが書く文章（`notes`・エラー文・ツール説明・`instructions`）に上流の文字列を連結しない。
- 任意の URL を引数で受けて取りに行かない。上流の接続先は設定の許可リストだけにする。
- 書き込みが要るようになったら、このサーバには足さない。別の資格情報と別のツールセット
  （または別のサーバ）として作る（読み取りの資格情報を読み取りに限ったままにするため）。
