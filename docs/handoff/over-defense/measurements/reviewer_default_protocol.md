# reviewer が省略時の既定値を余剰の HIGH にするかの確認（実行前に固定）

## 問い

`plugins/claq/agents/reviewer.md` の reviewer が、差分 D1（`verify_protocol.md`）の `request.args.get("q", "")` のような省略可能な引数の既定値を、「続行を決めた文の無い続行経路」として HIGH 以上にするか。

既定値 `""` は失敗の後に続行する経路ではない。`q` を省略した検索は要件「自分のノートを検索できる」の正常な呼び方で、`""` は全件に一致する検索語として振る舞いを決めている。これを HIGH にするのは誤り。

## 手順

1. 段階 1（現行の定義）: `verify/prompt_rev.md` をそのままサブエージェントへ渡して 3 回流す
2. 再現の定義: 3 回のうち 1 回以上、`q` の既定値を HIGH 以上（CRITICAL・HIGH・BLOCKER）の指摘にした
3. 段階 1 の 3 本は、別のエージェント 1 体が下の採点の項目を判定する（条件は 1 つなので伏せるものは無い）。再現しなければ、定義は変えずにクローズする
4. 再現したら、reviewer.md の余剰の節で「失敗の後に続行する経路」と「省略時の既定値」を区別する文に直し、段階 2 として同じプロンプトで 3 回流す
5. 採点: 段階 1 と段階 2 の出力 6 本を、版を伏せて番号を付け直し、順番を混ぜて、別のエージェント 1 体が下の項目を判定する

## 採点の項目（出力ごと）

- K: `q` の既定値（`request.args.get("q", "")`）を HIGH 以上にしたか（0/1）
- H1: `search_notes` の SQL インジェクションを CRITICAL または HIGH にしたか（0/1）
- H2: `get_note` の所有者検査漏れを CRITICAL または HIGH にしたか（0/1）
- X: 検索のレート制限・CSP・`_format_title` の長さ検査・DB の再試行のうち、HIGH 以上にした数

## 採用の規則

段階 2 の定義を採用するのは、段階 2 の 3 本すべてで K = 0、H1 = H2 = 1、X = 0 のとき。
