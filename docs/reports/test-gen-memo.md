# test-gen メモ（対応済み: 2026-08-27）

## 元の依頼

- `test-gen` スキルのステップ3-4「全関数のテーブルを提示 → 承認を待つ」から、承認を待つ意味の記述を**削除**する（「承認を待たない」と書き換えるのではなく、記述ごと消す）
- ルール「デシジョンテーブル承認前に実装を始めない」も同様に削除
- 他にも、全自動で完遂できず承認待ちで止まる記載がある agents/commands/skills をすべて見直す

## 対応

判定基準: **その停止を消したら、ユーザーが依頼していないことをコマンドが勝手にやることになるか。** ならないなら削除、なるなら維持し、維持する側には理由を定義本文へ書いた（次の監査で再提起されないように）。

### 削除した

| 箇所 | 内容 |
|---|---|
| `commands/test-gen.md` | description の「ユーザー承認」/ デシジョンテーブルの「承認を待つ」/ ルール「承認前に実装を始めない」/ ベースラインのテスト失敗確認（`red_baseline` として記録して続行） |
| `commands/review.md` | ステップ4の承認ゲート（承認・拒否・保留・無応答の 4 分岐）。特に「空入力・無応答 → 拒否扱いで停止」は、非対話文脈で /review が永久に何も直さないことを意味していた。READ-ONLY 制約はステップ1〜3 に残る |
| `skills/maintain/SKILL.md` | ステップ3の承認ゲート。description の「1回の実行で完了」と正面から矛盾していた |
| `skills/loop-dev/SKILL.md` | 「計画承認」の語 / レート制限 90% 超の「ユーザー確認」（checkpoint 保存と停止は残す） |
| `skills/adr/SKILL.md` | 初回のディレクトリ・テンプレート作成の確認（判断を含まない） |
| `skills/loop-audit/SKILL.md` | 日付解釈が曖昧な場合の確認（仮決定して Assumptions に載せる） |

### 維持した（理由を定義本文へ明記）

| 箇所 | 理由 |
|---|---|
| `commands/plan.md` の確認待ち | 成果物は計画そのもの。停止を消すと `/feat-dev` と同一になり存在理由が消える |
| `skills/adr/SKILL.md` の ADR 本文承認 | ADR は永続的な意思決定記録で、誤った ADR は以後の全判断を汚染する |
| `commands/harness.md` の `--apply` | 引数によるスコープ指定であって承認待ちではない（付ければ止まらない） |
| `commands/test-gen.md` の外部ライブラリ追加確認 | 依存追加は「テストを書く」依頼のスコープ外の永続的変更 |
| `skills/grillme/SKILL.md` | 質問して合意を作ることが職務そのもの |
| loop-dev の circuit breaker / turn cap / エスカレーション、refactor の CRITICAL/HIGH ブロック | 失敗時のエスカレーションであって承認ゲートではない |

`approved_plan` パラメータ名は変えていない。6 コマンドと loop-dev が共有する入力契約であり、意味は「plan 段の縮退」であって人間承認ではないため。
